# Install

Windows PowerShell commands install, update, uninstall, and inspect a per-user copy of the telephone line. They require no elevation and never write to Program Files, HKLM, a system service, or a startup entry. Install registers one per-user Task Scheduler task (`TelephoneLineWiredSupervisor`, hidden, limited-user, InteractiveToken) and two desktop shortcuts (`有线电话｜紧急停止` and `有线电话｜控制台`). Every location is caller input or documented per-user environment discovery, and the caller can always override it.

The registered task carries one UTF-16LE PowerShell `-EncodedCommand` action. This avoids Task Scheduler command-line quote/token drift while Doctor can still recover and verify the exact action script identity. The task remains hidden, limited-user, on-demand, and bound to the same logical install/state arguments.

v0.1 is Codex-first. Codex CLI is the currently built-in Lead. Other routes are execution or review sides, not substitute Lead entries.

## Commands

`src/install/Install-TelephoneLine.ps1` copies `src/`, `schemas/`, `docs/`, and `LICENSE` from a local `-SourceRoot` into `-InstallRoot` and publishes `install-manifest.json`. Product files are also staged in a content-addressed `versions/<source-sha256>/` directory. An atomic `current.json` pointer names the default version and changes only at a safe idle gate. `-SourceRoot` defaults to the product tree that contains the command. `-InstallRoot` defaults to `%LOCALAPPDATA%\TelephoneLine`, or to `TELEPHONE_LINE_INSTALL_ROOT` when that variable is set. `-AddToPath` is opt-in and per-user only; without it, no environment mutation occurs. A second install of the same source identity reports that the install is already current and re-registers the supervisor task and desktop shortcuts without rewriting dest files. `-Force` may replace an existing install after verifying that the manifest belongs to this product.

`src/install/Update-TelephoneLine.ps1` replaces installed files from a local `-SourceRoot`. It never contacts the network, a package registry, or a release endpoint. Durable runtime state and PATH posture are preserved. Active wired runs stay pinned to their recorded versioned Telephone core. If any line job under the resolved state root lacks a terminal receipt, update refuses with `IN_FLIGHT_JOBS_PRESENT` and changes nothing. If supervisor-owned runs are still pinned, update stages the new version directory, writes one durable `pending.json` at the base install root, and leaves the current pointer and dest product files unchanged. The version directory is only the pinned runtime; it is never the install root and never receives `pending.json`. After every exact pinned Job becomes idle, the run host (or a later idle supervisor) activates that pending version against the base install root automatically without Pascal rerunning Update: it atomically updates dest files, the install manifest, and `current.json`, retires pending through the recoverable deletion path, refreshes the scheduled-task and desktop surface, and never replaces bytes of a still-active version or PATH/state.

`src/install/Uninstall-TelephoneLine.ps1` pauses supervisor intake, precisely stops owned active Jobs and only the exact supervisor, unregisters the exact scheduled task and desktop shortcuts, then waits a bounded ownership/filesystem quiet gate (PID plus start ticks, Job membership, and locks). It recycles manifested product files, the version pointer, and versioned copies through the Windows recycle-bin path, including a bounded retry of a transient nonzero `SHFileOperation` after revalidating the exact unchanged target (no reparse, path escape, foreign live owner, or PID-reuse kill). It stops immediately when the target disappears, never falls back to direct or recursive delete, never signals unrelated processes, and recomputes install-root residue after each requested removal. Empty directories those files created are then removed. It does not delete an unmanifested file, does not remove the install root while unmanaged content remains, and does not recurse outside that root. Runtime state is preserved unless `-RemoveState` is passed and no in-flight line job exists; `-RemoveState` recycles the resolved line state root and supervisor state only after they are quiet. If a recycle remains blocked after the bounded gate, the command returns `RECYCLE_BLOCKED` and leaves evidence intact. Removing product files while the uninstall process still has those PowerShell definitions loaded is supported and does not require a reboot or a retained installed executable.

`src/install/Invoke-TelephoneLineDoctor.ps1` is read-only under every flag. Top-level `ok` is command execution success. `healthy` is product health. Doctor reports Windows and PowerShell adequacy, install-manifest identity including drift by relative path, validity of the eight adapter descriptors, bundled dashboard script and schema presence, optional dashboard config validity, state-root reachability, in-flight job count, and supervisor surface truth: manifest identity, exact scheduled-task action and principal, one supervisor owner, inbox/outbox/control availability, pause latch, active version and pinned versions, stale/PID-reused/orphan owners, and desktop controls. Installed inventory includes both the shared mailbox partition (`schemas/telephone-line-batch.schema.json` and the mailbox relay/collector) and the wired supervisor partition (`schemas/wired-supervisor-status.schema.json` and the supervisor scripts). It does not launch `codex`, `claude`, `cursor-agent`, `grok`, or DSH, and it does not run version or help probes against those CLIs. For each route it reports the declared `dependency_boundary` and states that the boundary is declared rather than probed. Uninstall stops only the exact dashboard watcher whose command line is the installed `Watch-TelephoneDashboard.ps1` and whose PID plus start identity still match, and only the exact supervisor.

## Environment

- `TELEPHONE_LINE_INSTALL_ROOT` — default install root when `-InstallRoot` is omitted
- `TELEPHONE_LINE_SOURCE_ROOT` — default source root when `-SourceRoot` is omitted
- `TELEPHONE_LINE_STATE_ROOT` — resolved state root for update, uninstall `-RemoveState`, and doctor when `-StateRoot` is omitted
- `TELEPHONE_LINE_SUPERVISOR_STATE_ROOT` — optional supervisor inbox/claimed/outbox/control root; when unset, supervisor state is `TELEPHONE_LINE_STATE_ROOT\supervisor` or `%LOCALAPPDATA%\TelephoneLine\supervisor-state`
- `TELEPHONE_LINE_USER_PATH_FILE` — optional file-backed per-user PATH store; when unset, `-AddToPath` uses the current-user Path environment variable
- `TELEPHONE_LINE_DASHBOARD_ENSURE_SCRIPT` — optional explicit observer launcher; when unset, the bundled dashboard is the default
- `TELEPHONE_LINE_DASHBOARD_OPT_OUT` — `1` / `true` / `yes` / `on` skips the bundled watcher
- `TELEPHONE_LINE_DASHBOARD_CONFIG` — optional `telephone-line-dashboard-config-v1` path
- `TELEPHONE_LINE_DASHBOARD_STATE` — dashboard runtime directory; default `%LOCALAPPDATA%\TelephoneLine\dashboard-runtime`
- `TELEPHONE_LINE_DASHBOARD_PROCESS_ENV_ONLY` — when set, override and opt-out are read from this process only
- `TELEPHONE_LINE_DASHBOARD_HEADLESS` — when set, the bundled watcher starts without a visible window
