# Telephone Line 0.1.7

This patch is the accepted cockpit status increment. Public source and download assets are on the repository [Releases](https://github.com/captpascallv-dev/telephone-line/releases) page. v0.1.6 and earlier version assets remain available.

Current roles use the actual dispatch or request identity after a real send: route, model, effort, and present state. Preallocated job ids, leftover package or route names, and a preparation token that happens to contain the word DISPATCH are not proof that an executor is running. `PREPARED_FOR_DISPATCH` is Lead preparing to send; actual in-flight work still uses `DISPATCHED` / request evidence.

Handled old executors and receipts move to history. Genuinely unhandled old work and valid parallel lanes stay current. A completed, accepted package folds; an unfinished project whose original owner is still working stays visible. A failed round stays a failure with the original owner already handling it; handler prose is not product acceptance and is not painted as normal progress.

PI and DeepSea v4 remain as previously accepted. This note does not claim new route measurements.

本补丁是已验收的驾驶舱状态增量。公开源码与下载资产在仓库 [Releases](https://github.com/captpascallv-dev/telephone-line/releases) 页。v0.1.6 及更早版本资产保留。

当前角色在真实派出后使用实际派发或请求身份：入口、模型、effort 和当下状态。预分配 job、残留包名或路线、以及仅因含 DISPATCH 字样的准备态，都不能证明执行者正在跑。`PREPARED_FOR_DISPATCH` 是负责人正在准备派出；真正在飞仍看 `DISPATCHED` / 请求证据。

已处理的旧执行和回执进入历史。真实未处理的旧工作和有效并行仍留在当前。已接受的完成包收起；原负责人仍在做的未完成项目保持可见。失败轮次保持失败，并由原负责人接手；处理说明不是产品验收，也不画成正常推进。

PI 与 DeepSea v4 保持此前已验收内容。本说明不声称新增路线实测。
