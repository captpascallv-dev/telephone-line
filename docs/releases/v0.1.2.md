## What 0.1.2 adds

Historical comparison is against the accepted 0.1.2 product-source baseline `e160d82771a6cb69a2f6d4701f39491b4c4ac935` (11 Sep 2026) and GitHub release v0.1.1:

- Wired supervisor after install remains the recommended first-use path. `Start-TelephoneLineJob.ps1` is the dispatch that run host invokes, and a compatible low-level entry when a supervisor run id is already inherited.
- The per-user supervisor continues after the Codex desktop process exits. That is process independence, not a claim that every AppData view equals the scheduled-task install. Doctor reports `SUPERVISOR_INSTALL_VIEW_MISMATCH` when those views differ; bind later commands to the physical install it already verified.
- Same-name supervisor tasks stay fail-closed across install roots (`SUPERVISOR_TASK_OWNED_BY_OTHER_INSTALL`). Non-owner `-RemoveState` refuses foreign supervisor or line state (`SUPERVISOR_STATE_FOREIGN`) and leaves that state in place. Same-owner no-console EXE tasks upgrade only through a verified `telephone-line-supervisor-wrapper-identity-v1` sidecar.
- Point the Lead CLI at an independent executable (`TELEPHONE_LINE_STABLE_CLI` / `stable-cli-policy.json`), not an App version folder.
- Batch wake uses a durable receipt/session/wake key. A proven same-key replay does not start a second executor or a second automatic callback. Missing writer identity or missing consumption evidence stays UNKNOWN. Trusted manual closeout of an already-read receipt is not recorded as automatic callback success.
- Automatic recovery reattaches proven same-run residue. Native-turn completion, process exit, and stdout/stderr EOF are recorded separately. Missing or unproven child/EOF evidence stays pending or UNKNOWN; it is not invented.
- Direct Cursor can register an explicit migration continuation for an interrupted native session. That is transport admission, not project acceptance.

User-oriented setup, Agent-assisted local setup, Codex-first authority, bilingual README, and macOS porting guidance in this tree stay in force. Windows remains the only v0.1 production target.

## Supported scope

- Windows is the only v0.1 production target. PowerShell 7 or later.
- Exactly eight execution/review routes. External Harnesses are user-installed; this package does not ship them.
- Per-user install, update, Doctor, and uninstall. No elevation. Runtime state stays outside the product tree.
- Existing transport obligations remain: exact original-session callback, no blind rerun of successful lanes, recoverable sealed state, and no absolute whole-task timeout.

## Install and use

1. Extract `telephone-line-0.1.2-windows.zip` from [Releases](https://github.com/captpascallv-dev/telephone-line/releases), or clone the source tree.
2. From that tree: `src/install/Install-TelephoneLine.ps1`, then `src/install/Invoke-TelephoneLineDoctor.ps1`. Dispatch only when Doctor reports `healthy=true` and `code=HEALTHY`.
3. Follow the recommended public path in [Quick start](../quick-start.md): independent background supervisor, then the normal `Start-TelephoneLineJob.ps1` dispatch under that owner, original-session callback, observer.
4. Keep bindings, task cards, and state outside the product install. Resolve identities on this machine; do not copy another machine's absolute paths.

## Validation status

These statements are about verification, not about which git commit or zip is currently attached on GitHub:

- Final product acceptance for 0.1.2 is not closed.
- A complete public install, recommended background path, original-CLI consumer callback, second-root ownership refusal, and same-owner wrapper upgrade have not been empirically completed on an independent Windows OS instance using that instance's own authorized CLI consumer.
- Isolated tests and local fixtures are not a substitute for a new user's machine. They do not prove every Windows consumer configuration.
