## What 0.1.3 adds

Historical comparison is against the accepted 0.1.2 product-source baseline `e160d82771a6cb69a2f6d4701f39491b4c4ac935` (11 Sep 2026) and GitHub Release v0.1.2:

- A GitHub-hosted Windows workflow, `windows-lifecycle`, installs the public Windows ZIP on a new `windows-latest` VM, runs ordinary Doctor, starts the registered scheduled-task supervisor, and runs one small deterministic local job through `Start-TelephoneWiredRun` / `Start-TelephoneLineJob`. That local job verifies install and background consumption. It is not an AI task and not an original-session Lead callback.
- The same workflow checks second-root install refusal, non-owner `-RemoveState` leaving foreign state in place, same-owner Update plus live wrapper identity, and Uninstall of owned content only.
- The workflow runs only on the validation branch `validation/telephone-windows-lifecycle-20260911` (push or `workflow_dispatch` of that branch). Existing `.github/workflows/ci.yml` smoke/full split is unchanged. Automatic `main` / `pull_request` events do not run this lifecycle.

Product runtime under `src/`, `schemas/`, existing tests, and `LICENSE` stays the accepted e160 identity. This candidate does not add product features, accounts, or extra permissions.

The official packager string in `src/packaging` remains **0.1.2**, so ZIP file names emitted by that packager still use `telephone-line-0.1.2-*.zip`. This note is the 0.1.3 candidate identity. A later Lead publication of tag v0.1.3 can bump the packager string together with `main` / Release.

## Supported scope

- Windows is the only v0.1 production target. PowerShell 7 or later.
- Exactly eight execution/review routes. External Harnesses are user-installed; this package does not ship them.
- Per-user install, update, Doctor, and uninstall. No elevation. Runtime state stays outside the product tree.
- Existing transport obligations remain: exact original-session callback, no blind rerun of successful lanes, recoverable sealed state, and no absolute whole-task timeout.

## Validation status

These statements are about verification, not about which git commit or zip is currently attached on GitHub:

- Final product acceptance is not closed by this note.
- The Windows lifecycle workflow covers a GitHub-hosted runner VM, that job's default login, and a deterministic local consumer. It does not prove every Windows user's interactive desktop, arbitrary non-admin logins, paid-model execution, or Pascal-host AI callback/process drain.
- Historical private combination F (independent private Windows plus that machine's authorized AI consumer) was not executed. The current publication-validation combination is this GitHub Windows install lifecycle plus Pascal-host real AI consumption collected by the original Lead. CI local work is not that AI consumption.
- Isolated tests and local fixtures are not a substitute for a new user's machine.
