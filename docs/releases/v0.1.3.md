## What 0.1.3 changes

- Desktop shortcuts keep the existing user-visible names `有线电话｜紧急停止` and `有线电话｜控制台` and the same control-script targets. Creation uses Unicode `IShellLinkW` / `IPersistFile` so English-codepage Windows can save those names. Same-owner update and uninstall remove those owned names only; other `.lnk` files on the same desktop stay. A failed shortcut save remains an install failure.
- The official packager and `schemas/release-manifest.schema.json` version constant are **0.1.3**. Official ZIP names are `telephone-line-0.1.3-source.zip` and `telephone-line-0.1.3-windows.zip`. The repository `release-manifest.json` is the complete official inventory (`files`, `counts`, `excluded`) with artifact bytes/SHA left null. A filled external copy of that same shape may record the two ZIP bytes/SHA; it does not add extra fields.
- A GitHub-hosted workflow, `windows-lifecycle`, packages those official assets from the checked-out tree, installs the public Windows ZIP on `windows-latest`, runs ordinary Doctor, starts the registered scheduled-task supervisor, and runs one deterministic local command through the public `Start-TelephoneWiredRun` generic command entry. The same job checks second-root install refusal, non-owner `-RemoveState` leaving foreign state in place, same-owner Update plus live wrapper identity, and Uninstall of owned content only.

- The local CI command now measures real process stdout/stderr pipe EOF through a capture parent that starts a small worker, keeps Process plus both readers until OS exit, and writes observation only after both reader tasks reach EOF. The worker does not self-report EOF or exit success.
- Lead drain may return at native completion only after handing the original Process and stdout/stderr readers to an in-process OpenDrain holder. The unique reader owner does not exit. Child stdout/stderr EOF and a measured child exit are not the reader-host OS exit; Wait does not wait for a still-alive calling host to exit itself. Reader-ready/child EOF does not set recovered or clear host drain pending while that host is still alive. Exact owned leftover with no live business descendants, no queued callback, and not a shared Codex App may be recycled; original readers still record the real OS exit and EOF. Foreign PIDs are refused. Historical 7de8 UNKNOWN is not rewritten.
- The bundled dashboard shows the current workstream only. Ended work is replaced only when a later job on the same project and the same Lead session (or an explicit valid successor identity) has observed continuation (live command/relay, receipt, or delivery). Same Lead plus project is not automatic replacement: independent nonempty package stages stay separate current rows. A later receipt on another Lead, or the same project and worktree alone, does not replace an unresolved independent obligation. Unstarted recovery, current-task failure, stuck callback, duplicate live owners, and independent parallel failures stay visible. Exact job id alone does not clear `FRESH_DIRECT_SESSION_REQUIRED`. The watcher sleeps the remainder of its configured interval from observation start and does not stamp a stale observation as healthy.
- Named supervisor jobs no longer kill CommandHost or Relay when the RunHost handle closes. Cancel still uses `TerminateJobObject` after reconstituting a named job that still has live survivors, and only after exact pid/start and run/lineage membership; PID-only records are not adopted. Completed outbox requires a valid bound `telephone-line-delivery-v1` record, not a retrying or malformed relay-error. Automatic supervisor/RunHost recovery retains one exact relay; `Restore-TelephoneExactJobRelay` uses an exclusive restore lock so competing recoverers cannot start duplicate collectors. The original command runs once. Wake acknowledgment requires a positively validated protocol/run/session identity before any App Server fallback. OpenDrain lifecycle files must match the expected process/session/run before they count as a measured terminal; missing drain records stay UNKNOWN.
- An outstanding callback (this job has `CALLBACK_MISSING` or `RECEIPT_AWAITING_DELIVERY` and no delivery) stays a visible current row until an exact successor identity or a still-live same-obligation successor. A later same-Lead/same-stage receipt or delivery without that binding does not hide the old obligation. Independent same-Lead packages on distinct stages stay separate.
- Wait/Stop completed recovery accepts only `telephone-line-host-terminal-v1` with the bound host identity and genuine required reader EOF. A host-terminal file that has only `exit_code`, or the wrong protocol/session/PID/start, stays pending and does not set recovered. Child EOF, reader-ready, host absence, or a file merely named host-terminal is not host completion.
- Supervisor completion and live ownership share one decision path: even a consumed wake/delivery cannot write completed while the exact owned command, relay, named-job member, or other live owned work is still alive. Current named-job membership plus recorded and survivor evidence all govern that decision; a missing or stale job-members snapshot is not evidence of death, and a known live job member cannot drop out of terminal truth. Named job membership is ownership, not an exemption. Bare mailbox `collector_pid` or a pid-only owner hint never exempts a live owned process. A leftover shared collector may outlive command/relay only when the current mailbox `telephone-line-wired-supervisor-mailbox-v1` corresponds to this run and Lead (run id, session, identity hash and key) and the matching lead `telephone-line-mailbox-owner-v1` at that key proves the same pid, start, and collector role. Unrelated protocol-shaped owner records and PID-only ancestor walks do not grant that role. Wake `wake_run_id`/`wake_key` must correspond to delivery and consumption authority; a generic `AUTOMATIC_WAKE_ACK` flag is not sufficient. Partial/malformed/foreign/absent proof fails closed. Competing automatic RunHost restore still yields one new relay, one original mailbox/wake continuation, and command count 1.
- Zero/nonwaiting drain observation inspects registered process/stdout/stderr/completion tasks without blocking. An explicit WaitMilliseconds budget is shared across those waits. Incomplete readers stay owned until real EOF; observation does not dispose, kill, or stamp EOF early.
- Host-terminal completion is recorded only by an external host-stream observer (`owner_reader_completion` or `open_drain_completion`). Overlay host-terminal is intent-only (`host_exit_intent`; `process_exited`/`stdout_eof`/`stderr_eof` remain false). Host-role OpenDrain requires actual stdout/stderr reader tasks and does not Dispose the caller Process.
- App-server overlap no longer swallows `DURABLE_CHAIN_INVALID`. Bind publishes `turn_start_sending` before the bound-turn write. Foreign `thread_id` on bound-turn in that window rejects.

The local CI command verifies install and background consumption. It is not an AI task and not an original-session Lead callback. CI does not measure paid-model behavior.

The workflow runs only on the validation branch `validation/telephone-windows-lifecycle-20260911` (push or `workflow_dispatch` of that branch). Existing `.github/workflows/ci.yml` smoke/full split is unchanged. Automatic `main` / `pull_request` events do not run this lifecycle.

## Supported scope

- Windows is the only v0.1 production target. PowerShell 7 or later.
- Exactly eight execution/review routes. External Harnesses are user-installed; this package does not ship them.
- Per-user install, update, Doctor, and uninstall. No elevation. Runtime state stays outside the product tree.
- Existing transport obligations remain: exact original-session callback, no blind rerun of successful lanes, recoverable sealed state, and no absolute whole-task timeout.

## Public use and Actions

- Install from the Windows ZIP using `src/install/Install-TelephoneLine.ps1` as documented in [Install](../install.md).
- Ordinary Doctor: `src/install/Invoke-TelephoneLineDoctor.ps1`.
- Background work uses the registered scheduled task `TelephoneLineWiredSupervisor` and the public `src/supervisor/Start-TelephoneWiredRun.ps1` command entry.
- The `windows-lifecycle` workflow is the public Actions entry for this install/background/ownership combination. It uses `contents: read` only.

## What this CI cannot prove

- Arbitrary interactive desktop users outside the runner login.
- Non-admin or other Windows SKUs beyond the GitHub-hosted `windows-latest` image used by the workflow.
- Paid model execution or original-session AI callback and process drain on a user's own machine.
- Isolated tests and local fixtures are not a substitute for a new user's machine.

Final product acceptance is not closed by this note.
