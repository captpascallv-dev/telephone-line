# Privacy boundary

The public telephone line stores transport identities, not project content.

- Prompts and stdin may be referenced by path, byte length, and SHA-256. Their bytes are not copied into dispatch metadata, logs, manifests, receipts, relay errors, wake prompts, or summaries.
- Durable errors use stable transport error codes and bounded generic public messages. Unknown error text is rejected and replaced with a generic public message. Truncation of raw input is not sanitization.
- Raw external exception text, prompt or stdin bodies, credential-like values, account or email values, and absolute local-user paths are not stored in receipts, relay-error records, wake prompts, or summaries.
- Lead continuation uses a frozen `telephone-line-lead-binding-v1` object: exact session id, worktree, and a caller-supplied launcher. The core does not read account identity, subscription files, or provider-specific run records.
- DeepSea subscription routes keep OAuth tokens in a DSH-owned store (default `%USERPROFILE%\.dsh\subscription-oauth.json`, overridable by `TELEPHONE_LINE_DSH_SUBSCRIPTION_STORE`). If the community `dsh-plugin-subscriptions` store is present, the same login is reused from the user DSH home (`%USERPROFILE%\.dsh\plugins\subscriptions\auth.json`) and from the DSH Desktop harness home (`%APPDATA%\dsh-desktop\harness\plugins\subscriptions\auth.json`). `TELEPHONE_LINE_DSH_COMMUNITY_STORE` may replace that community discovery with semicolon-separated store files, or `off` to disable community reuse. `TELEPHONE_LINE_DSH_CODEX_COMMUNITY_KEY` selects a non-secret community Codex slot key; it is not a credential. They do not copy, login, export, or persist credentials into telephone-line job state, and they do not load PI coding-agent.
- Direct Cursor may take `-CursorAgentRoot`, else `TELEPHONE_LINE_CURSOR_AGENT_ROOT`, else a user-local `%LOCALAPPDATA%\cursor-agent` install. That path is a declared user-installed CLI location, not a machine identity stored in telephone-line state.
- Install, update, uninstall, and doctor resolve `%LOCALAPPDATA%\TelephoneLine` or `TELEPHONE_LINE_INSTALL_ROOT`, `TELEPHONE_LINE_SOURCE_ROOT`, `TELEPHONE_LINE_STATE_ROOT`, optional `TELEPHONE_LINE_SUPERVISOR_STATE_ROOT`, and optional `TELEPHONE_LINE_USER_PATH_FILE`. Those values stay caller configuration. Supervisor durable records live under the supervisor state root (`inbox`, `claimed`, `outbox`, `runs`, `control`) and store transport identities, PID and start ticks, request hashes, and terminal codes, not prompt bodies.
- The bundled dashboard reads only shipped public schemas plus caller-configured descriptor files and StateRoots (`TELEPHONE_LINE_DASHBOARD_CONFIG`, `TELEPHONE_LINE_DASHBOARD_STATE`, optional `TELEPHONE_LINE_STATE_ROOT`, optional descriptor `supervisor_state_root`). It does not embed a local user path, account, thread id, private registry, token, or GitHub dependency in the package. It does not write supervisor or task state.
- Runtime locations are supplied by the caller. The core has no machine-local default path, username, or private project name.
- Requests, intents, receipts, claims, and deliveries are create-new objects. Tampered or unknown fields fail closed.
- This candidate does not include credentials, transcripts, live receipts, telemetry, billing, or hosted-service configuration.
- The Codex app-server Lead-side adapter may persist hashes, owner identity, a default service-tier binding, and a deterministic non-sensitive wake marker. It does not persist raw callback text, thread history, command text, file-change contents, reasoning, tokens, credentials, approval/user-input payloads, or raw app-server stderr. Pending state is method/id only. Trusted inbound transitions are bound to the exact thread and turn; nonbound payloads are not stored. Stderr is drained so the process cannot deadlock, and only bounded categorical counts are stored. Public failures use fixed categorical messages on every public entry, including profile and launcher scripts; truncation of exception text is not sanitization.
